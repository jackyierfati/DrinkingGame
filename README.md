# 🍻 喝酒转盘 DrinkingGame

一个「转盘选词条、满足条件就喝酒」的小游戏。纯前端（HTML/JS，无需构建），
手机浏览器直接打开即用，以后可以用 Capacitor / 套壳打包成 App。

## 玩法

1. 点「转起来」，转盘停在一个词条上，例如「年纪最大的人喝一口」「转盘右边的人喝两口」。
2. 满足条件的人按提示喝。
3. 可以按分类筛选（位置 / 属性 / 身份 / 群体 / 挑战 / 规则）。
4. 新的一局换一批人时，点「重置这一局」清空出现记录。

## 核心设计

### 1. 优先级防重复（你提的重点）

- 每个词条有一个 `priority`，初始为 **0**。
- 被转到一次，`priority -= 1`。
- 抽签权重 = `base × 2^(priority × 6)`：
  - `priority 0` → 权重 1（没出现过，最容易被抽到）
  - `priority -1` → 权重 ≈ 0.016（出现过，几乎不会马上再出现）
- 于是没出现过的词条**总是优先**被转到，天然轮换、基本不重复。
  模拟跑满一整轮 142 次抽取，重复只有个位数。
- `priority` 存在 `localStorage`，关掉重开记忆还在；换局用「重置」清空。

参数 `EntryDB.ANTI_REPEAT`（`js/db.js`）控制防重复强度，越大越不容易重复。

### 2. 转盘怎么用上「几千条」词库

盘面一次只显示 8 格（太多看不清），但这 8 格是从**整个词库**里按优先级
**加权抽出**的候选。转中哪条，哪条 `priority -1`，下一把重新抽候选。
所以词库有几百上千条都行，转盘始终只展示当前最该出现的一批。

### 3. 词条怎么「生产」（解决 4000 条的问题）

不手写几千条，而是**模板 × 主语 × 动作**组合生成（见 `js/entries.js`）：

```
主语（位置/属性/身份类，共 ~36 个）  ×  动作（喝一口/喝两口/干了/罚一杯…）
+ 群体类整句（所有男生喝…）
+ 挑战类整句（说三个明星名字，说不出就喝…）
+ 规则类整句（免死金牌 / 你来指定谁喝…）
```

当前默认生成 **142 条**，全部自动去重。要扩量：

- 调大 `generateEntries(actionsPerSubject)` 里每个主语搭配的动作数（最多用满 7 个动作）。
- 往 `POSITION / ATTRIBUTE / IDENTITY` 加更多主语，往 `CHALLENGE / RULE` 加更多整句。
- 再引入新维度（如「N 秒内…」「连续两轮…」「谁谁一起…」）可组合出上千条。

> 说句实话：4000 条**高质量**中文词条本质是内容活，代码只能保证「不重复地批量组合 + 防重复轮换」。
> 现在这套框架能无痛扩到上千条；真要冲 4000，建议把词条做成可编辑的数据表（见下），边玩边加最省力。

## 后续可做

- 词条改成可在界面里**增删改**，存 IndexedDB（现在是代码内生成）。
- 支持**导入/导出 JSON** 词库，方便攒到几千条。
- 加音效、震动、历史记录。

## 目录结构

```
index.html        页面
styles.css        样式（暗色、移动端优先）
js/entries.js     词条生成器（模板组合 + 去重）
js/db.js          词库 + 优先级持久化 + 加权抽取
js/wheel.js       Canvas 转盘（绘制 + 旋转动画）
js/app.js         组装：界面 ↔ 数据库 ↔ 转盘
```

## 本地运行

直接用浏览器打开 `index.html` 即可；或起个静态服务：

```bash
python3 -m http.server 8080
# 打开 http://localhost:8080
```
