# 🍻 喝酒转盘 DrinkingGame

一个「转盘选词条、满足条件就喝酒」的小游戏。纯前端（HTML/JS，无需构建），
手机浏览器直接打开即用，以后可以用 Capacitor / 套壳打包成 App。

## 功能

- **两种模式**（顶部开关切换）：🎡 转盘 / ✨ 随机闪现（词条飞速跳动后定格，视觉更炫）。
- **随机喝多少**开关：开=每次随机附带酒量，关=只说喝、不定量。
- **📖 词条管理**：顶部按钮，弹窗里可**搜索、新增、编辑、删除**词条，出现过的会划掉。
  - 通过 `node server.js` 访问时，改动存**服务端**（`data/custom.json`），全场共享、下次还在；
  - 直接开 `index.html`（无服务端）则存本机浏览器。
  - 基础词库（代码里的）只读，编辑/删除会以「覆盖层」形式记录，不改动原文件。
- **🔇 音乐**：顶部按钮。默认用浏览器实时合成的欢快循环（无版权、离线可用）；
  若你放了自己有版权的 `assets/bgm.mp3`，会自动优先播放它并循环。
  > 抖音视频里的 BGM 是版权音乐，不便打包进公开仓库，所以没有直接内置。

## 玩法

1. 点「转起来」，转盘停在一个词条上，例如「买过网红爆款产品的人」「被电瓶车撞过的人」。
2. 符合「…的人」条件的人就喝。
3. 可以按分类筛选（习惯 / 经历 / 才艺 / 爱好 / 其他）。
4. 新的一局换一批人时，点「重置这一局」清空出现记录。

## 核心设计

### 1. 优先级防重复（你提的重点）

- 每个词条有一个 `priority`，初始为 **0**。
- 被转到一次，`priority -= 1`。
- 抽签权重 = `base × 2^(priority × 6)`：
  - `priority 0` → 权重 1（没出现过，最容易被抽到）
  - `priority -1` → 权重 ≈ 0.016（出现过，几乎不会马上再出现）
- 于是没出现过的词条**总是优先**被转到，天然轮换、基本不重复。
  模拟跑满一整轮 142 次抽取，重复只有个位数。
- `priority` 存在 `localStorage`，关掉重开记忆还在；换局用「重置」清空。

参数 `EntryDB.ANTI_REPEAT`（`js/db.js`）控制防重复强度，越大越不容易重复。

### 2. 转盘怎么用上「几千条」词库

盘面一次只显示 8 格（太多看不清），但这 8 格是从**整个词库**里按优先级
**加权抽出**的候选。转中哪条，哪条 `priority -1`，下一把重新抽候选。
所以词库有几百上千条都行，转盘始终只展示当前最该出现的一批。

### 3. 词条从哪来（解决「生产词条」的问题）

词库 = **视频扒的真实词条** + **同风格扩写词条**：

1. **真实词条**（`js/entries-data.js`，216 条）
   从 3 个抖音转盘视频（「随机喝酒大转盘」「今天谁喝酒」「1000个喝酒大转盘」）
   **逐帧抄录**下来的原汁原味词条，符合条件的人就喝。两种句式：
   - 「…的人」经历/习惯类：买过网红爆款产品的人、看过至少五部恐怖片的人
   - 「…的喝」条件类：B型血的喝、头发染过色的喝、被欺骗过感情的喝
   分十类：习惯 / 经历 / 才艺 / 爱好 / 感情 / 饮食 / 外形 / 性格 / 互动 / 其他。

2. **同风格扩写**（`js/entries.js` 的 `expandEntries()`）
   照着视频里的句式，用「模板 × 词槽」扩写更多，风格统一、量能上去：
   - `每天{X}的人` / `每周{X}的人`（生活习惯）
   - `看过{N}部{类型}的人`（影音）
   - `被{X}过的人`（经历遭遇）
   - `能{X}的人` / `会{X}的人`（才艺）
   - `{做过/去过…}的人`

当前合计 **273 条**（216 真实 + 扩写，自动按文本去重）。要继续扩量：往
`js/entries.js` 顶部的 `DAILY / WEEKLY / SEEN / PASSIVE / ABLE / CAN / DONE`
这些词槽里加词即可，加几个词就多几十条。

#### 怎么再从视频扒更多词条

`tools/extract_frames.sh` 用 `ffmpeg` 抽帧（`mpdecimate` 只留画面明显变化的帧，
自动跳过模糊的旋转过程）。把转盘视频给我，我按帧读取顶部大字结果、抄成词条、
去重后加进 `entries-data.js`。

> 说句实话：4000 条**高质量**词条本质是内容活。一个 14 秒的视频大概只有几十条；
> 靠「真实词条打底 + 同风格扩写 + 多扒几个视频」滚起来最实在。下一步建议把词条做成
> 界面里可增删改 + JSON 导入导出（见下），边玩边攒最省力。

## 运行

**最省事**：直接用浏览器打开 `index.html`。

**起服务端**（推荐，手机能连、行为更接近真机）：

```bash
node server.js            # 默认 8555 端口
PORT=3000 node server.js  # 指定端口
# 或： npm start
```

启动后会打印本机和局域网地址。也可用 `./serve.sh` 走 Python。

## 远程访问（让别人也能点开来玩）

应用状态存在各自浏览器里（localStorage），所以每台设备是**独立的一局**——
适合「一台机当主持、投屏大家看」，或每人手机各转各的。

**① 同一 WiFi（最简单，零配置）**
启动 `node server.js`，看它打印的 `局域网访问` 地址（形如
`http://192.168.x.x:8555`），同 WiFi 的手机浏览器直接打开即可。

**② 外网访问，用内网穿透（推荐，安全、免动路由器）**
不用开公网端口，用隧道工具把本地端口映射出去，会给你一个临时公网网址：

```bash
# 任选其一（需自行安装）
cloudflared tunnel --url http://localhost:8555
# 或
ngrok http 8555
```

把它给你的那个 https 网址发给朋友就能远程玩。关掉即失效，安全。

**③ 外网访问，用家里公网 IP + 端口转发（要小心）**
在路由器后台把「外部端口 → 你电脑内网IP:8555」做端口转发，别人用
`http://你的公网IP:外部端口` 访问。注意：
- 这等于把服务暴露到公网，任何人都能访问，务必**只在玩的时候开、玩完就关**；
- 家里公网 IP 通常是动态的（会变），要长期用得配 DDNS；
- 很多家宽是大内网（NAT），根本没有公网 IP，这种方式行不通——用方式 ②。
- ⚠️ **端口别撞车**：`8123` 是 HomeAssistant 的默认端口，若你已在用 HA，
  游戏请换端口（默认已用 `8555`），并把路由器转发指到**运行游戏这台机器**的内网 IP。

> 那需要把优先级放到服务端存储 + 简单接口。需要的话我可以加。
